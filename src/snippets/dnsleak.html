什么是 DNS 泄露

打开网址的第一步是解析域名：设备先问一台 DNS 服务器「这个域名对应哪个 IP」，拿到地址才能连接。这一步由递归解析器完成，通常是运营商自动下发的那台，也可能是你手动填的 8.8.8.8、1.1.1.1、223.5.5.5。它从根、顶级域、权威服务器一路查下来，再把结果返回给你。

这一步和网页流量走不走代理是两件独立的事。浏览器插件式代理只接管 HTTP(S) 请求，一部分只改路由、不改 DNS 配置的 VPN 客户端也一样。结果是：网站看到的是代理出口的地址，你的运营商却能看到你查询过的每一个域名。这就叫 DNS 泄露（DNS Leak）。

DNS 泄露在某些场景下比 IP 泄露暴露得更具体：IP 说明你在哪，域名记录说明你在访问什么。看到它不需要解密任何流量，HTTPS 也挡不住，因为 HTTPS 加密的是连接内容，不是你查询过的域名。

这次检测做了什么

  1. 浏览器生成 8 个互不相同的一次性随机子域，形如 {32 位随机串}.edns.ip-api.com。
  2. 同时通过 HTTPS 请求这些地址。这些名字从未出现过，任何缓存里都没有，每一个都必须由你的递归解析器去问 ip-api.com 的权威服务器。
  3. ip-api.com 的权威服务器记下来问的那个地址，并在这次请求的响应里返回给浏览器。
  4. 页面把收集到的解析器地址发给本站，补上国家/地区、ISP 与 ASN，再和你的 HTTP 出口对照，得出结论。

为什么发 8 个而不是 1 个：公共 DNS 的递归侧是一组机器，每次查询从哪一台发出是随机的，只发一个只能看到其中一台，多发几个才能看出这组机器的范围。子域用一次就丢，也避开了缓存：任何一层缓存命中，这次检测就无效了。

怎么读检测结果

  • 解析器与出口同属一个 ASN：DNS 和网页流量走同一条路。要么没用代理，要么代理已经接管了解析，这是最干净的情况。
  • 解析器是知名公共 DNS，且与出口在同一国家/地区：没有跨境泄露，但你的域名记录交给了这家服务商，能否接受取决于你是否信任它。
  • 解析器是本地运营商，出口却在别处：典型的 DNS 泄露。代理只接管了网页流量，域名查询仍然经过本地网络。
  • 一个解析器都没抓到：请求没能到达 ip-api.com。常见原因是网络限制、或浏览器扩展拦下了这些请求。这不代表安全，只是这次没测出来，换个网络再试。

如果结果里有 ECS 一项，说明解析器把你所在的网段（EDNS Client Subnet，RFC 7871）告诉了权威服务器。这样 CDN 能就近调度，代价是每个权威服务器都能知道你大致在哪个网段，即使 DNS 本身没有跨境。

如何防止 DNS 泄露

  • 让 VPN 客户端接管 DNS。这是最彻底的一条。 WireGuard 在配置里写 DNS = ， OpenVPN 在 Windows 上用 block-outside-dns， 商业客户端一般有「阻止 DNS 泄露」开关。工作在 TUN 模式、接管整个网络栈的客户端天然没有这个问题。
  • 启用 DoH / DoT。浏览器和系统都支持把解析加密后发给指定服务商。 注意它换的是「交给谁」和「路上会不会被看」，不等于不再有人知道你访问了什么。
  • 检查系统与路由器的 DNS 配置。很多泄露的根源是路由器上写死了运营商 DNS， 设备层面怎么改都会被 DHCP 覆盖回去。
  • 关掉 IPv6，或确认 IPv6 也走隧道。只接管了 IPv4 的代理配上双栈网络， DNS 会顺着 IPv6 那条路原样漏出去，这是最隐蔽的一种。

改完之后回到本页再测一次即可验证。每次检测都用全新的随机子域，不会读到上一次的缓存。

常见问题

挂着 VPN，为什么 DNS 还是走运营商？
因为解析发生在连接之前。系统要先把域名换成 IP 才知道往哪里发包，而用哪台 DNS 由网卡配置决定。只接管 HTTP(S) 的浏览器插件式代理，以及一部分只改路由、不改 DNS 的 VPN 客户端，都不会改这份配置。结果是网站看到的是代理出口，你的运营商却拿到了你访问过的每一个域名。
检测出来的地址和我填的 8.8.8.8 对不上，是不是测错了？
没错，这是这项检测最容易被误读的地方。8.8.8.8 是你提交查询的入口，权威服务器看到的是 Google 递归集群里实际发出查询那台机器的地址，通常在 74.125.x 或 172.253.x。两者属于同一家、同一个 ASN，但不会是同一个地址。所以本页按 ASN 而不是按 IP 识别服务商。
为什么一次检测会冒出好几台解析器？
公共 DNS 的递归侧是一组机器，每次查询从哪一台发出是随机的；很多系统还同时配置了主备两组 DNS。本页发起多个互不相同的随机子域，就是为了看出这组机器的范围，它们都拿到了你要访问的域名。
开了 DoH / DoT 加密 DNS，还需要测吗？
需要，结论可能和你想的不一样。加密解决的是路上有没有人能看到查询，不解决最终由谁来查。DoH 只是把明文查询换成发给某家服务商的 HTTPS 请求，这家服务商照样知道你在访问什么。本页测的正是这一点：最终是谁替你去问权威服务器。
本站会保存 DNS 检测结果吗？
不保存。随机子域由 ip-api.com 的公开 EDNS 服务解析，它能看到你的解析器地址、ECS 网段和你的 IP，按其自身政策处理。页面随后把解析器地址和你的出口 IP 发给本站查询归属，本站不记录这次检测，归属查询结果按 IP 短时缓存，不与检测关联。
