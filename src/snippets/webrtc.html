什么是 WebRTC 泄露

WebRTC（Web Real-Time Communication）是浏览器内置的实时音视频与点对点数据传输能力， 网页版视频会议、屏幕共享、在线客服、云游戏串流基本都用它。 点对点通信要先解决一个问题：两台设备都在 NAT 后面，彼此不知道对方的公网地址。 WebRTC 用 ICE 框架解决：浏览器向 STUN 服务器发一个请求， 服务器把「我看到你来自哪个地址和端口」返回给它，这个结果叫 srflx（server reflexive）候选地址。

问题在于：ICE 收集地址走的是 UDP，直接由操作系统的网络栈发出， 不经过浏览器的 HTTP 代理设置。 所以网页流量走着 VPN 或代理，网站看到的是代理出口； 同一个页面里的 JavaScript 发起 ICE 收集， 拿到的却是你本地宽带的真实公网地址。这就是 WebRTC 泄露（WebRTC Leak）。

泄露的不只是公网地址。ICE 还会收集 host 类型的候选地址，也就是网卡上的内网地址 （192.168.x.x、10.x.x.x 这类），能暴露你所在局域网的网段。 Chrome、Edge、Firefox 大约从 2019 年起默认用 mDNS 主机名 （形如 a1b2c3d4-….local）替换真实内网地址，这部分风险已经小了很多， 但公网地址这条路至今仍然开着。

这次检测做了什么

  1. 对清单里的每一台 STUN 服务器，单独建立一个 RTCPeerConnection，只填这一台作为 ICE 服务器。
  2. 创建一条数据通道并生成 offer，触发浏览器开始 ICE 候选地址收集。
  3. 逐条读取收集到的候选地址，按类型分开：srflx / relay 是公网地址，host 是本机地址。
  4. 补查 IPv4 与 IPv6 的 HTTP 出口，只比较同协议族地址；IPv6 隐私地址按 /64 网段归并。没有同族 HTTP 地址时保留为无法比较。

为什么一台一台单独测，而不是把所有服务器一起放进 iceServers： 放在一起时浏览器只给出去重后的候选地址，分不清是哪台服务器回的、哪台没通。 分开测才能看出「国内的 STUN 通、国外的全超时」这类情况， 这也是清单里国内外服务器都有的原因。某一台超时不代表你安全，只说明那台没连上。

怎么读检测结果

  • 没有探到任何公网地址：本次没有取得公网候选；可能是网络限制、浏览器策略或 STUN 服务不可用，不能据此保证安全。
  • 与已知同族 HTTP 出口一致：本次没有看到额外出口；IPv6 按 /64 比较，不代表所有 UDP 都经由代理。
  • 与同族 HTTP 出口不同：多出口、分流或代理设置都可能造成差异，需要结合实际路由复查，不能直接认定为泄露。
  • 没有同协议族地址可比较：例如只有 HTTP IPv6 与 STUN IPv4，不将它们直接判为一致或泄露。
  • 探到 192.168 / 10.x 开头的内网地址：你的浏览器没有启用 mDNS 混淆，局域网网段被暴露了。

如何防止 WebRTC 泄露

最直接的办法是装一个扩展，在浏览器里限制 WebRTC 的地址收集。 下面两个都是 Chrome 应用商店里现成的扩展，装好后刷新本页重测即可确认：

  • WebRTC Network Limiter 由 Google 发布，修改的是 Chrome 的 WebRTC 策略：只使用代理所走的那条路径，保留视频通话功能，同时不再暴露真实地址。
  • WebRTC Protect — Protect IP Leak 一键开关式的拦截扩展，直接禁掉 WebRTC 的地址收集。适合完全用不到浏览器内音视频通话的人。

除了装扩展，还有几种做法：Firefox 用户可以在 about:config 里把 media.peerconnection.enabled 设为 false， 代价是网页版音视频通话完全不可用； 使用支持全局 TUN / TAP 模式的 VPN 客户端，让 UDP 也走隧道，从根本上去掉这条旁路； 或者在路由器上封掉 STUN 常用的 3478 端口。 注意：禁用 WebRTC 会让 Google Meet、腾讯会议网页版、Discord 网页版这类服务失效， 如果日常要用，优先选 Network Limiter 这种限制策略的方案，而不是完全关闭。

常见问题

用了 VPN，为什么还会被查到真实 IP？
多数浏览器插件式代理和 SOCKS / HTTP 代理只接管 TCP 上的 HTTP(S) 流量，WebRTC 的 ICE 收集走 UDP，直接从物理网卡发出，绕过了代理设置。这不是 VPN 的 bug，而是分层设计的结果，除非 VPN 以 TUN 模式接管整个网络栈。
检测显示全部超时，是不是说明我很安全？
不能这么判断。超时只说明这些 STUN 服务器当前连不上（网络限制、服务器故障、UDP 被封）。换个网络、换台服务器，结果可能完全不同。即使取得的候选与同族 HTTP 出口一致，也只能说明本次未观察到额外出口，不能保证所有流量安全。
内网地址显示成一串 .local 是什么意思？
这是 mDNS 混淆，浏览器用一个随机主机名替换了真实内网地址。这是预期中的正常行为，说明你的浏览器版本已经带上了这项保护。
本站会保存 WebRTC 检测结果吗？
不会。整个检测都在你的浏览器里完成，候选地址不会发回本站服务器。页面上的地址只存在于当前标签页，关掉即消失。
