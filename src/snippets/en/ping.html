What global ping is

Ping is the oldest and most common network diagnostic: send an ICMP Echo request to a target and wait for an Echo reply. The round trip is the latency (RTT), and the share of requests without a reply is the packet loss. But running ping on your own computer only ever measures the one route from you to the target.

Global ping runs the same test from around the world: probes in different countries and ISP networks ping the same target at once, and the results are shown side by side. Use it to check a server's latency to China and to your users before buying it, to see whether visitors in different regions connect quickly after a site launches, to check that every region hits a nearby node after a CDN switch, or just to tell whether the problem is your own network or the server is really down. A ping from your own machine can't answer any of these.

Probes on this page come from Globalping, a free, open-source probe network maintained by the jsDelivr team, with probes hosted by volunteers and organizations around the world.

What this check does

  1. The input is checked in your browser: only public IPv4 / IPv6 addresses or dotted domain names are accepted; private, reserved and localhost addresses are rejected. A full URL also works; the script takes the host name from it.
  2. The browser submits one measurement to Globalping directly: 1 probe in each of 13 regions, 3 packets each; with TCP, it does 3 handshakes with port 443 on the target instead.
  3. Progress is fetched from Globalping once a second and each row fills in as its probe finishes; polling stops when all are done or after about 30 seconds.
  4. The summary shows the number of reachable probes, the fastest and slowest regions, and the addresses the target resolved to in each region.

Domains are resolved locally by each probe, not on your computer before sending. Sites that use GeoDNS or a CDN may resolve to different addresses in different regions. The "Resolved addresses" field lists every address returned in this run, and rows that differ from most probes are marked.

Reading the results

  • Avg latency is the mean of three round trips, colored in four tiers: under 100 ms is good (same city or nearby regions usually take a few to a few dozen milliseconds), 100–200 ms is OK, 200–350 ms is slow (typical for intercontinental routes), and above 350 ms is poor.
  • A large gap between min and max means noticeable jitter; latency-sensitive uses (gaming, voice, remote desktop) will feel it.
  • Packet loss is marked when it is not 0. Losing 1 of 3 packets is 33%; a one-off is not a concern, but loss in several regions at once is worth investigating.
  • Unreachable means this probe got no reply to any packet. In ICMP mode the most common cause is that the target blocks ping; switch to TCP 443 and try again. Only if TCP also fails does it mean the target really can't be reached from that region.
  • No probe available means Globalping has no probe online in that region right now. It has nothing to do with the target; try again later.

Each row shows the city, AS number and ISP of the probe that actually ran the measurement. The next run may use a different probe in the same region, and the numbers will change with it. When comparing two runs, first check whether the ISP is the same.

FAQ

Why do some probes show "Unreachable" when the site opens fine?
ICMP ping and opening a website are different kinds of traffic. Many servers, cloud security groups and corporate firewalls drop ICMP by default, so every ping times out while ports 80 / 443 keep serving. In that case switch the method to "TCP 443" and test again: if TCP works, the server is online and just doesn't answer ping; if TCP fails too, the target really can't be reached from that region.
What's the difference between ICMP and TCP 443, and which should I use?
ICMP is classic ping and measures the network-layer round trip, which is good for judging the route itself. TCP 443 measures the time to complete a three-way handshake with port 443 on the target. It is not affected by ICMP filtering and is closer to the connection time when a browser opens an HTTPS site; values are usually similar to ICMP or slightly higher. Use ICMP for server routes, and TCP for websites or when you get "Unreachable".
What does "measurement quota used up" mean?
Globalping's anonymous API counts quota per exit IP, about 250 "probe runs" per hour. One run on this page uses 13 probes, so you get roughly a dozen or more runs per hour. The quota recovers on a rolling hourly basis, so wait a bit and try again. Requests go straight from your browser, so the quota is yours alone and other visitors can't use it up.
Why do mainland China probes often have no result, or a different city each time?
Globalping probes are hosted by volunteers and organizations, and there are few public probes in mainland China, often offline. Each measurement picks one of the probes online at that moment at random, so the city and ISP may change each time; go by the city and AS number shown in the row. When a region happens to have no probe online, its row shows "No probe available".
Does this site record the targets I ping?
No. Measurement requests go straight from your browser to Globalping (api.globalping.io); this site's server neither relays them nor receives the target you enter. After a measurement starts, the address bar changes to /ping#host=… so a reload or shared link is prefilled: the part after # is a URL fragment, which the browser does not send with requests, so it never appears in this site's access logs. The only exception is old links in the /ping?host=… form: the query string after the question mark is part of the request, so opening it once is recorded in the standard access log like any visit, and the page immediately rewrites the address to the # form. Note that Globalping, as a third party, receives the target you enter and your IP address; it keeps measurement results on its platform for a while under its own policy, and anyone with the measurement ID can view them.
