What a browser fingerprint is

Browser fingerprinting is a stateless way to identify you. A cookie is a marker a site writes to your device and reads back on the next visit; you can delete or refuse it. A fingerprint writes nothing. It collects the attributes your browser already tells every site and computes a hash as your ID. Deleting cookies doesn't help, nor does private mode, because nothing is stored.

A single attribute carries little information; billions of people use Chrome. But combine dozens and the chance of a match drops fast: a 2560×1440 screen, the Asia/Shanghai time zone, 187 installed fonts, an Apple M2 GPU, a specific trailing digit in a floating-point value from the audio stack… each extra attribute multiplies the number of possible combinations. The EFF's Panopticlick experiment in 2010 showed that among browsers with Flash or Java enabled, more than 90% of samples were unique.

How the three algorithms differ

FingerprintJS v3+

The mainstream open-source implementation today. The biggest change in v3 is what it keeps: instead of collecting as much as possible, it keeps only signals that stay stable across sessions. Fields like User-Agent, which change with every update and are easy to fake, are heavily down-weighted or dropped; signals tied to hardware and the OS, such as Canvas rendering differences, WebGL GPU and driver info, audio processing traits and font metrics, carry the weight. The result is more stable: on the same device, the visitorId usually stays the same across networks and time zones. This page loads v3.4.2, the MIT-licensed open-source version, computed entirely locally without network access.

FingerprintJS2 (legacy)

The version widely used from 2015 to 2020, with a broader scope: plugin list, Flash fonts, touch support, CPU class, the Do-Not-Track flag and more. Browsers have since weakened or blocked most of these (Chrome stopped exposing the real plugin list long ago), so on modern browsers the legacy hash is actually less stable than v3. It's kept for comparison: when the two algorithms disagree on the same device, that shows how much browsers have tightened privacy in recent years.

JA3 / JA4

The first two run in JavaScript and can be disrupted by changing browser settings or installing an anti-fingerprinting extension. JA3 / JA4 work at a different layer: they read the first message the client sends in the TLS handshake (the ClientHello) and hash the TLS version, cipher suites, extensions, elliptic curves and point formats concatenated in a fixed order. These are set by the browser's underlying TLS library and can't be changed by JavaScript on a page, so they identify which version of which browser (or which scraping library) you use, not which device. JA4, released in 2023, splits the hash into readable segments and is harder to evade. CDNs and fraud systems use it heavily to spot automation pretending to be a browser: a UA that says Chrome with a TLS handshake that looks like Python requests is easy to catch.

Note: JA3 / JA4 have to be computed by a server that can read the raw TLS handshake, and this site's web server doesn't have access to that layer. So this option makes your browser send one request directly to a third-party TLS echo service and fetch the result. The request does not go through this site, and this site neither receives nor stores the response. If you don't want that external request, don't select this option.

What fingerprints are used for

  • Fraud prevention: banks, payment providers and e-commerce sites use it to spot mass sign-ups, promo abuse and account takeover from one device. This is the main and most legitimate use.
  • Ad tracking: as third-party cookies are phased out, fingerprints have become an alternative for cross-site tracking: products you viewed on site A show up in ads on site B.
  • Bot detection: JA3 / JA4 in particular are used to tell real browsers from disguised automation.
  • Account linking: platforms use it to tell whether several accounts come from one device, to ban alt accounts or catch fake-order rings.

How to make fingerprinting harder

  • Tor Browser: the most thorough option today. Instead of hiding, it makes every user look the same: uniform window sizes, a uniform font list, and blocked Canvas reads.
  • Firefox resistFingerprinting: set privacy.resistFingerprinting to true in about:config to spoof the time zone and block Canvas and WebGL reads. Some sites may display incorrectly.
  • Brave: by default adds random noise to Canvas and audio signals per site and per session, so fingerprints don't match across sites.
  • Anti-detect browsers: common for running many accounts; each profile gets its own consistent set of fingerprint parameters.

One counterintuitive point: piling on anti-fingerprinting extensions can make you easier to recognize. A browser with randomized Canvas output, a decade-old UA and WebGL blocked is a statistically rare combination, and that alone becomes a conspicuous fingerprint. What works is looking like most other users, not standing out.

FAQ

Does private mode prevent fingerprinting?
No. Private mode deals with local traces: no history is saved and cookies are cleared on exit. Fingerprints don't depend on stored data; they read hardware and system attributes, which are identical in a private window. Open this page in a private window to compare.
Does changing IP or using a VPN change my fingerprint?
No. FingerprintJS v3 and v2 compute attributes of the browser and device, unrelated to your network exit; JA3 / JA4 compute the TLS handshake, which is also unrelated to IP. That is why fingerprints can link the same device across different IPs.
Why does the legacy value change on every reload?
Some signals the legacy version relies on (Canvas in particular) get fresh noise each time in browsers with anti-fingerprinting protection, so the result is unstable. It also shows your browser does have some protection on.
Does this site store my browser fingerprint?
No. v3 and v2 are computed entirely in your browser, and the results are not sent back to this site. JA3 / JA4 need one request to a third-party TLS echo service; the result likewise stays on this page and does not pass through this site's server.
