What "China user" detection in Claude means

Anthropic does not serve mainland China, and its official endpoints block access by region. Being flagged while still able to connect matters more than being blocked. Public reverse-engineering found that when Claude Code is pointed at an unofficial relay via ANTHROPIC_BASE_URL, it reads the OS time zone and the relay hostname, then encodes the result steganographically in the "Today's date is …" line of the system prompt: with a China time zone, the date separator changes from - to /; the apostrophe switches between four visually near-identical Unicode variants to encode whether the hostname matched a domain list or AI-lab keywords. These markers go to the server with every request and are invisible to the eye.

Detection is not a single switch; it adds up several weak signals into a probability. The system time zone weighs the most: it accompanies every request and is hard to fake by accident. Language, fonts, device brand and network exit add weight on top. A US time zone combined with a full set of Chinese fonts and a WeChat WebView still reads as suspicious. The browser reveals this much because regional settings reach into many places: the system time zone drives Intl and Date, language preferences drive navigator.languages and the Accept-Language header, and installed system fonts can be measured pixel by pixel on a canvas.

What this check does

  1. Read the system time zone resolved by Intl.DateTimeFormat. It is the only signal where a web page and Claude Code read the same value, so it has the highest weight (24 points).
  2. Check the regional settings in turn: browser language list, Intl locale and UTC offset.
  3. Measure glyph widths on a canvas to detect Chinese and Chinese-vendor fonts. Whether a font is installed shows up directly in the rendered width.
  4. Identify Chinese browsers, in-app WebViews and device brands from the UA and UA-CH.
  5. Have WebRTC gather ICE candidates from a STUN server once to see whether it reveals a local or public address, and compare it with the address this site sees at the HTTP layer.
  6. Each signal gets a "China similarity" between 0 and 1, multiplied by its weight and summed. The 10 weights add up to 100, so the total is the risk score.

Every probe only reads browser APIs, and the values never leave this page. Signals light up one at a time instead of all at once so you can see which ones raise the score, and know which to change first.

This page only looks at the browser environment. To see which country Claude and ChatGPT actually see your exit IP in, and whether it is a supported region, use AI access check. To see which exit every site uses, use Split routing test.

Reading the results

  • 0–30 low risk: no obvious China traces in the visible browser fingerprint. This does not mean the account is safe: exit IP, payment method and account behavior are outside what this page can see.
  • 31–60 medium risk: several fingerprints point to a Chinese environment, enough together to put risk controls on alert. Usually either time zone or language matches, plus some fonts.
  • 61–100 high risk: several high-weight signals match at once. Under the disclosed mechanism, such an environment marks every request as "looks like a China user".
  • Colors per signal: a score ≥ 0.25 counts as a match (amber), ≥ 0.6 as a strong match (red). The "+N" on the right is the points that signal actually contributes: similarity × weight.

Taiwan is not on Anthropic's restricted list, so the Asia/Taipei time zone and zh-TW language / locale score nothing, and Traditional Chinese fonts keep only a very small score (Taiwan cannot be told apart from Hong Kong and Macau). Hong Kong and Macau are restricted regions, so related signals keep a partial score.

How to lower the risk score

Ordered by weight, highest first. Each step maps to one signal above; run the check again after each step:

  1. Change the system time zone. Switch the OS time zone to one outside China (for example America/New_York or Europe/London), and confirm getTimezoneOffset() is no longer UTC+8. This single step has the largest effect. If you run Claude Code through a relay on a host in China, also override it with the TZ environment variable.
  2. Reorder languages. Remove zh-CN / zh-Hans from the top of your browser and system language lists so that navigator.languages and Accept-Language start with English or another non-Chinese locale.
  3. Isolate Chinese and vendor fonts. Fonts such as Microsoft YaHei, PingFang, MiSans and HarmonyOS Sans are measurable on a canvas as soon as they are installed. Running Claude in a clean browser profile or a separate system environment is more practical than uninstalling fonts one by one.
  4. Block WebRTC and use a residential exit. First confirm in this site's WebRTC leak test that your real address does not leak; prefer a residential IP over a data-center IP so the network exit does not undo an otherwise clean environment.
  5. Relay hostname. When Claude Code goes through a relay, the hostname in ANTHROPIC_BASE_URL is the second of the two signals it reads. A web page cannot see it, so this check does not score it.

One more point: disguising every signal to the extreme is itself a fingerprint. An English time zone with a full set of Chinese fonts, or a browser with a single language in its list, is just as rare statistically. The goal is to look like an ordinary user outside China, not to show nothing at all.

FAQ

Does Claude really read my time zone?
According to public reverse-engineering, when Claude Code is pointed at an unofficial endpoint via ANTHROPIC_BASE_URL, it reads the OS time zone and the relay hostname, then hides the result in the "Today's date" line of the system prompt using a few visually near-identical Unicode characters. The time zone this page reads through Intl.DateTimeFormat is that same system time zone.
Is this score Claude's actual verdict?
No. Of the ten signals, only the system time zone maps directly to the disclosed mechanism; the other nine are related "Chinese environment" fingerprints. Anthropic's actual risk controls also look at the exit IP's owner, payment method, account age and usage patterns, none of which a web page can see. The score is an estimate, not a conclusion.
Does a low score mean I won't be banned?
No guarantee. This page only measures fingerprints visible to the browser; a data-center exit or a high-risk virtual card can still get an account flagged. A low score removes obvious tells in your local environment, not all risk. Use the IP check on the home page to see whether the exit address is residential and whether it has proxy history.
Will the score change if I switch IPs or use a VPN?
Mostly not. Time zone, language, fonts and device model come from the OS and browser, not the network exit, which is why many "clean" VPN setups still score high here. Only the WebRTC signal depends on the network.
Does this site store the results?
No. Every check runs in your browser, and the detected time zone, language, fonts and device details are not sent back to this site. The WebRTC signal sends one request to a STUN server; the address it returns stays on this page and disappears when you close it. The "Check history" at the bottom of the page stores only the score, level and names of matched signals in your browser, none of the detected values; click "Clear" to delete it.
