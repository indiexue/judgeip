Why test ChatGPT and Codex separately

ChatGPT web, sign-in, static assets, the mobile app and Codex / API use different OpenAI domains: the web app is chatgpt.com, sign-in goes through auth.openai.com, scripts and styles come from cdn.oaistatic.com, and Codex CLI, IDE extensions and API calls all request api.openai.com. When a proxy routes by domain, one missing rule is enough to get half-broken setups: "web works, Codex reports a network error", or "Codex works, web sign-in keeps spinning".

This page reads Cloudflare's /cdn-cgi/trace once per endpoint to get the exit IP, country and colo that endpoint sees, then measures latency three times and takes the median. If endpoints exit in different countries or one fails, the verdict names it.

Reading the results

  • ChatGPT web works, Codex / API fails: api.openai.com is not covered by your proxy rules, or is blocked on its own. Add it to the same rule as chatgpt.com, pointing at the same node.
  • Sign-in and auth fails: the web app gets stuck on the sign-in page and codex login cannot complete browser authorization.
  • Web static assets fail: chatgpt.com itself connects, but the page is blank and buttons do nothing.
  • Endpoints exit in different countries: web and Codex requests from one account arrive from two countries, one of the most common risk-control triggers.
  • IPv6 notice: when OpenAI sees an IPv6 exit, a separate notice appears at the top. Geolocation data for IPv6 is generally less accurate than for IPv4, and proxy IPv6 exits are often whole hosting ranges. Disable IPv6 for OpenAI domains or make the system prefer IPv4.

FAQ

Codex reports a network error but ChatGPT web works. Is OpenAI down?
Check the "Codex / OpenAI API" row first. If it fails while ChatGPT web works, your local routing rules almost certainly don't cover api.openai.com. If both rows are fine, check the service status page for an OpenAI outage.
If my exit is in a supported region, is my account safe?
Not necessarily. Hosting IPs, frequent node switching, a browser time zone that doesn't match the exit, and payment details that don't match the exit can all trigger risk controls. To see whether the exit IP is residential or hosting and has proxy history, paste it into the lookup on the home page.
Does this site record the results?
Nothing is sent back to this site. All requests go straight from your browser to each OpenAI endpoint, without cookies or a referrer. The "Check history" at the bottom of the page lives only in your browser's localStorage (exit address, country and verdict, up to 20 entries); click "Clear" to delete it.
