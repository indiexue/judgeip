为什么要把 ChatGPT 和 Codex 分开测

ChatGPT 网页、登录、静态资源、手机 App 与 Codex / API 用的是 OpenAI 的不同域名： 网页是 chatgpt.com，登录走 auth.openai.com， 页面脚本与样式来自 cdn.oaistatic.com， Codex CLI、IDE 插件和 API 调用则全部请求 api.openai.com。 代理软件按域名分流时，规则只要漏写一个，就会出现「网页正常、Codex 报网络错误」或「Codex 能用、网页登录转圈」这类只坏一半的情况。

本页对每个入口各读一次 Cloudflare 的 /cdn-cgi/trace，拿到的就是那个入口看到的出口 IP、国家与机房， 再测三次延迟取中位数。几个入口的出口国家不一致、或其中一个连不上，结论里会直接点出是哪一个。

怎么读检测结果

  • ChatGPT 网页能开，Codex / API 不通：api.openai.com 没有被代理规则覆盖，或被单独拦截。 把它加进与 chatgpt.com 相同的规则、指向同一个节点。
  • 登录与认证不通：网页会卡在登录页，codex login 也无法完成浏览器授权。
  • 网页静态资源不通：chatgpt.com 本身能连上，但页面白屏、按钮没反应。
  • 几个入口的出口国家不同：同一个账号的网页与 Codex 请求会从两个国家进来，这是风控最常见的触发条件之一。
  • IPv6 提醒：OpenAI 看到的是 IPv6 出口时，页面顶部会单独提示。IPv6 的地理库数据普遍不如 IPv4 准， 代理的 IPv6 出口又多是整段机房地址，建议对 OpenAI 的域名关闭 IPv6 或让系统优先使用 IPv4。

常见问题

Codex 报网络错误，但 ChatGPT 网页一切正常，是 OpenAI 故障吗？
先看本页「Codex / OpenAI API」那一行。它不通而 ChatGPT 网页正常，几乎都是本地分流规则没有覆盖 api.openai.com；两行都正常再去「服务状态」页看 OpenAI 是否在故障中。
出口在支持地区，账号就一定安全吗？
不一定。机房 IP、频繁切换节点、浏览器时区与出口对不上、支付信息与出口不符，都可能触发风控。出口 IP 是家宽还是机房、有没有代理记录，可以复制到本站首页查询。
本站会记录这次检测的结果吗？
不会发回本站。所有请求都由你的浏览器直接发给 OpenAI 的各个入口，不带 Cookie、不带来源页面。页面下方的「检测历史」只存在你本机浏览器的 localStorage 里（出口地址、国家与结论，最多 20 条），点「清除」即删除。
