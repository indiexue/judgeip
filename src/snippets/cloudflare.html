什么是 Cloudflare 节点

Cloudflare 在全球三百多个城市部署了数据中心，所有接入 Cloudflare 的网站共用这张网络。访问这些网站时，你的请求不会直接到达网站的源服务器，而是先落到 Cloudflare 的某一个边缘机房，由它完成 TLS 握手、缓存命中与安全过滤，再决定要不要回源。这个机房就叫节点（Cloudflare 内部称为 colo），用就近机场的 IATA 三字码命名：HKG 是香港，NRT 是东京成田，LAX 是洛杉矶，FRA 是法兰克福。

Cloudflare 用任播（Anycast）把同一个 IP 同时宣告在所有机房，由互联网路由决定你最终落到哪一个。理想情况下这就是离你最近的那个；但运营商的国际出口、与 Cloudflare 的互联关系、目标站点的套餐等级都会改变这个结果，所以同一个人访问不同网站，延迟可能差出几百毫秒。

每个走 Cloudflare 的站点都有一个公开的诊断地址 /cdn-cgi/trace，它用几行纯文本告诉你：命中的机房（colo）、它看到的出口 IP（ip）与国家（loc）、HTTP 与 TLS 版本、SNI 是否加密、密钥交换算法，以及 WARP、Zero Trust 网关是否在用。本页的全部结论都来自这几行字。

这次检测做了什么

  1. 向 speed.cloudflare.com/cdn-cgi/trace 连续请求两次：第一次只为建立连接，第二次的结果才展示。第二次请求前后各记一次本机时间，取中点与边缘时间对照，得出时钟偏差（边缘时间只精确到秒，偏差也只报到整秒）。
  2. 向本站查询「本站看到的你的 IP」的归属：运营商（ASN）、城市与大致坐标，和首页显示的是同一份数据。trace 本身不给坐标，所以只有当这条地址与上一步 Cloudflare 看到的出口是同一个（IPv4 相同，或 IPv6 同在一个 /64 网段）时，才用它来算你和节点之间的距离；不是同一个出口，就只按国家判断远近。
  3. 请求 https://1.1.1.1/cdn-cgi/trace：IP 字面量只能走 IPv4，看到的是你的 IPv4 出口与 1.1.1.1 所在网络的落点。
  4. 对下表 7 个不同等级的 Cloudflare 网络，各预热 1 次、再连续请求 3 次，取最快的一次作为延迟，同时记下命中的节点与协议。最多 4 个网络同时测，避免互相抢带宽。
  5. 从 challenges.cloudflare.com 加载 Cloudflare Turnstile，用非交互、托管两种模式的组件各跑一次人机验证；拿到的 token 交给本站服务器，向 Cloudflare 复核一次（见下文）。

发往 Cloudflare 的请求（第 1、3、4 步）都不带 Cookie、不带来源页，也不附加任何自定义请求头（加了会触发跨域预检，而 trace 地址不响应预检），结果只留在当前页面里，不会发回本站。 第 2 步是向本站自己查询，请求里不带任何检测结果，本站从中看到的只有你的 IP，和你打开本页时一样。 Turnstile 那一步的 token 必须由服务端复核才算数，本站服务器复核完即丢弃，不保存 token 与结果，只按你的 IP 记一个 1 小时后过期的复核次数，用来限流。

怎么读检测结果

  • 命中节点与距离：距离在 1000 公里以内，或节点在你出口的周边（中国大陆访客命中香港、台北、东京、大阪、首尔、新加坡，这已经是境外网络能给到的最近落点），或与出口同在一个国家/地区且不超过 3000 公里，算就近接入；其余 3000 公里以内的，或与出口同在一个国家/地区的（美国、俄罗斯、巴西这样的大国，境内跨几千公里也不算绕到别的地区），算区域内；剩下的是跨区接入，延迟会明显偏高。没取到你的坐标、算不出距离时，同国或周边的节点照样算就近接入，其余只标中性的「已识别」，不判远近。距离按本站查到的出口 IP 的大致坐标估算，只是一个量级参考；Cloudflare 看到的出口与本站看到的不是同一个地址时，这份坐标不适用，不估算距离。
  • 出口 IP：与本站看到的同族地址一致，说明访问 Cloudflare 和访问本站走的是同一个出口；同族却不同，说明有分流或多出口代理；一个 IPv4、一个 IPv6 则只是双栈网络下各走各的，属于正常现象。
  • HTTP/3：首次访问通常为 HTTP/2，浏览器记住站点支持 HTTP/3 之后才会改走 QUIC，刷新后再测即可。HTTP/1.1 则往往意味着中间有一层不支持新协议的代理。
  • TLS、ECH 与后量子：TLS 1.3 是当前标准；SNI 显示「加密（ECH）」说明连沿途的网络设备也看不到你访问的域名；密钥交换里出现 MLKEM 或 Kyber，表示这条连接已经用上了抗量子计算的混合密钥交换。
  • WARP / Zero Trust 网关 / 远程浏览器隔离：任何一项开启，Cloudflare 看到的都不再是你直连的出口，节点与出口 IP 要按 WARP 或公司网关的出口来理解。
  • 时钟偏差：trace 给的边缘时间只精确到秒，偏差因此只按整秒估算；估出来相差 3 秒及以上（真实偏差至少 2 秒上下）会单独标出。时钟不准会导致 TLS 证书校验、两步验证码等出问题。

为什么不同网络会命中不同节点

Cloudflare 的套餐决定了站点能用哪些机房、走哪条线路。企业版站点可以用上全部节点与更优的路由，中国网络（与京东云合作）只在中国大陆访客访问时才调度到境内节点，1.1.1.1 的 DNS 与 WARP 网络使用独立的任播地址段，测速站与 cdnjs 也各有各的调度。所以对比表里各行命中不同的节点很常见；如果全部落在同一个就近节点，说明你的网络到 Cloudflare 的路由非常理想。

对比表里没有「免费版」：本站不在 Cloudflare 上，找不到一个能长期确定仍是免费套餐的第三方站点。如果你自己有免费套餐的站点，在浏览器里打开它的 /cdn-cgi/trace，对照 colo= 一行即可。

Turnstile 人机验证测的是什么

Turnstile 是 Cloudflare 用来替代传统验证码的人机验证：它在后台读取浏览器环境、执行一小段质询，再结合 Cloudflare 对这个 IP 与网络的了解，判断访问者是不是真人。越来越多的网站在登录、注册、评论、下载这些地方用它挡机器人。如果浏览器总是过不了它、或者每次都要点一下，这些网站用起来就会处处卡顿。

本页用两个不同模式的组件各跑一次验证，看你的浏览器能不能不做任何操作就自动通过：

  • 非交互模式（Non-interactive）：组件只显示一个进度，从不出现可以点的复选框。Cloudflare 满意就直接发放 token，不满意就直接判失败，它最直接地回答「你能不能无感通过」。
  • 托管模式（Managed）：由 Cloudflare 决定要不要请你点一下。多数正常的浏览器会自动通过；信号不够干净时，组件里会出现「确认您是真人」的复选框，点一下才放行。本站首页手动查询 IP 时用的就是这种模式。

卡片上的「响应耗时」是从页面开始验证到拿到 token 的时间，需要点击时也包括你点击之前的等待。拿到 token 之后，页面把它交给本站服务器，由服务器连同你的 IP 向 Cloudflare 的 siteverify 接口复核一次：token 是否有效、是不是第一次使用、是不是本站这张卡片签发的（hostname 与 action 要对得上）。前端拿到 token、服务端也复核通过，才算真正通过。「响应元数据」里列着复核时 Cloudflare 返回的各项字段（经本站筛选、限长）；其中的 cData 由页面自己与本次渲染时生成的随机值对照，只标出是否一致供你核对，不计入判定。

托管模式没让你点就通过了

说明在 Cloudflare 看来，这个浏览器和这条网络都像普通访客：出口 IP 的信誉正常、浏览器特征前后一致、没有明显的自动化痕迹。这是最理想的结果，在其他使用 Turnstile 的网站上，你多半也看不到验证框。

要求点击确认，或者非交互模式没通过

这只说明 Cloudflare 没能自动认定你是真人，不等于被封锁。常见原因有：出口是数据中心、VPN 或代理的地址（同一出口上机器流量多，信誉自然偏低）；隐私类扩展或防指纹浏览器改动、拦截了浏览器特征；浏览器带有自动化特征（例如被 Selenium、Playwright 控制）；本机时钟与真实时间相差太大；或者网络太慢，质询没能在时限内完成。换一个出口、暂时关掉相关扩展后点「重置」再测，通常就能看出是哪一项造成的。Cloudflare 的判定只基于它能看到的信号，本页如实转述结果，但无法告诉你它具体看重了哪一项。

卡片显示「脚本加载失败」，说明浏览器没能从 challenges.cloudflare.com 加载 Turnstile：所在网络屏蔽了这个域名，或者扩展、代理规则拦下了它。这种情况下，任何使用 Turnstile 的网站都会卡在验证这一步。显示「长时间未加载」则是 15 秒内脚本还没就绪：可能被拦截，也可能只是到 challenges.cloudflare.com 的网络很慢——脚本晚些到达时，卡片会自动开始检测。卡片上注明是本站部署问题的错误（例如 110200：当前域名不在 Widget 的允许列表里）出在本站的配置上，与你的浏览器无关。

常见问题

人在国内或亚洲，为什么命中的是美国的节点？
Cloudflare 的调度看的是网络而不是地图：你的请求落到哪个机房，取决于运营商的国际出口、Cloudflare 与这家运营商的互联关系，以及目标站点的套餐等级。中国大陆访客访问没有接入中国网络的站点时，常被调度到洛杉矶（LAX）、圣何塞（SJC）这类美国西海岸机房，企业版站点更容易落在香港、东京、新加坡。这是调度策略的结果，不代表你的网络出了故障。
Cloudflare 看到的出口 IP 和本站看到的不一样，是怎么回事？
先看两个地址是不是同一族。一个是 IPv4、一个是 IPv6 很正常：双栈网络下，浏览器访问本站和访问 Cloudflare 时可能各自选了不同的地址族，两条都是你自己的出口。如果两个都是 IPv4（或都是 IPv6）却不一样，说明访问 Cloudflare 的流量走了另一个出口，常见于按域名分流的代理规则，或者带多个出口的代理服务。
为什么显示 HTTP/2，而不是 HTTP/3？
浏览器要先通过一次 HTTP/2 连接收到 Alt-Svc 响应头，才知道这个站点支持 HTTP/3，之后的新连接才会改走 QUIC。所以首次访问通常为 HTTP/2，刷新几次后变成 HTTP/3 是正常的。如果一直停在 HTTP/2，多半是网络屏蔽了 UDP 443，或者你用的代理不支持转发 QUIC。这不影响正常浏览。
WARP、Zero Trust 网关、远程浏览器隔离分别是什么？
WARP 是 Cloudflare 的客户端加速与加密服务，开启后网站看到的是 WARP 的出口，plus 表示 WARP+（付费的 Argo 线路）。Zero Trust 网关（Gateway）表示你的流量正经过某个组织配置的 Cloudflare 安全网关，多见于公司设备。远程浏览器隔离（RBI）表示网页其实在 Cloudflare 的远程浏览器里运行，你看到的只是渲染结果。三项都显示未启用，说明你是直接连到 Cloudflare 的。
Turnstile 测试要我点一下才通过，是我的网络有问题吗？
不一定。托管（Managed）模式由 Cloudflare 根据浏览器与网络信号决定要不要请你点一下：多数正常的浏览器会直接通过，而出口是数据中心、VPN 或代理的地址，装了改动浏览器特征的隐私扩展，浏览器带有自动化特征，或者本机时钟不准时，被要求点击的概率会明显升高。点一下就能通过，说明只是没能「无感」通过，并不是被封锁。非交互（Non-interactive）模式不会出点击框，Cloudflare 不满意就直接判失败，所以它更能说明你能不能自动通过。
本站会记录这次检测的结果吗？
不会。节点检测的请求都由你的浏览器直接发往 Cloudflare 的各个站点，不带 Cookie、不带来源页，trace 内容与节点结果只显示在当前页面里，不会发回本站，关掉页面即消失。算节点距离用的大致位置，是页面向本站查询「本站看到的你的 IP」得到的，和打开首页时的那次查询是同一份数据，请求里不带任何检测结果。Turnstile 检测拿到的一次性 token 会交给本站服务器，连同你的 IP 向 Cloudflare 复核一次后即丢弃；本站只按 IP 记一个 1 小时后自动过期的复核次数，用于限流。
