什么是 AI 解锁检测

ChatGPT、Claude、Gemini 这些服务都按访问者的 IP 判断地区：OpenAI、Anthropic、Google 各自公布了一份支持地区名单， 中国大陆、香港、澳门、俄罗斯、伊朗等地区不在名单上。从这些地区访问，轻则打不开、要求反复验证， 重则注册失败、付款被拒、账号被停用。所谓「解锁」，就是让这些服务看到一个位于支持地区的出口。

麻烦在于，你以为的出口不一定是它们看到的出口。代理软件开在「规则」模式时，每个域名按规则各走各的路： chatgpt.com 可能走了美国节点，api.openai.com 却因为规则没写全而直连；claude.ai 走了日本，api.anthropic.com 走了香港。 本站服务器只看得到你连到本站的那一条线路，回答不了这个问题——必须让每一家服务自己报一次「我看到你从哪里来」。

这次检测做了什么

  1. 对接入 Cloudflare 的服务，读它的 /cdn-cgi/trace：这是 Cloudflare 边缘对每个接入站点都开放的诊断地址， 回一段纯文本，其中 ip 是这家服务看到的出口 IP、loc 是 Cloudflare 判定的国家、 colo 是你命中的机房。这正是这家服务做地区判断时看到的信息。
  2. 对同一个地址再发三次只测时间的请求，取中位数作为延迟。第一次请求往往带着 DNS 解析与 TLS 握手，单测一次会把延迟报高一截。
  3. Google 与 DeepSeek 不经过 Cloudflare，网页读不到它们看到的出口，只测连不连得上、有多快。 DeepSeek 是国内参照：海外 AI 全部打不开而它正常，说明网络本身是通的，问题出在代理或拦截上。
  4. 拿每一行的 loc 对照下方各家的支持地区名单；再拿浏览器时区与语言对照出口所在的国家， 把本站看到的地址与 AI 服务看到的出口摆在一起。

所有请求都由你的浏览器直接发出，不带 Cookie、不带来源页面，结果只留在当前页面上，不会发回本站，也不保存历史。

怎么读检测结果

  • 地区「支持」：这家服务看到的出口在它的官方支持地区内。这是能正常使用的前提，但不是全部—— 出口 IP 是家宽还是机房、有没有代理记录，可以把出口 IP 复制到本站首页查询。
  • 地区「不支持」：出口落在官方名单之外。不建议用这样的出口登录，先把这家的域名分流到支持地区的节点。
  • 地区「可能受限」：这家没有公布逐国名单，出口落在常见的受限地区（制裁地区与中国大陆），仅作提示。
  • 几家的出口国家不一致：分流规则把 AI 服务分到了不同节点。不同服务之间问题不大， 同一家的几个入口（网页版与 API）不一致才值得处理——同一个账号的请求在两个国家之间来回切换，是风控最常见的触发条件之一。
  • 「时区与出口不一致」：浏览器时区与出口所在国家的时区相差超过一小时。网页和客户端都读得到系统时区， 这是识别代理成本最低的线索。邻近地区之间（例如上海与新加坡）不会报这一条。
  • 「不可访问」：请求超时或被拒绝。若只有个别服务打不开，多半是这几个域名没有被代理规则覆盖， 也可能是对方正在故障，可以先到服务状态页确认。

地区名单由本站对照各家官方页面手工整理，名单会随政策调整，判断以官方页面为准。 Cloudflare 的 loc 与各家自己的地理库偶有出入，尤其是刚换过归属的 IP 段——结果是风险提示，不是对账号命运的判决。

常见问题

地区显示「不支持」，账号一定会被封吗？
不一定，但风险是实打实的。OpenAI、Anthropic、Google 都公布了支持地区名单，名单之外的地区它们不提供服务：从这样的出口注册或登录，常见的结果是反复要求验证、付款失败、功能受限，严重时账号被停用。反过来，出口在支持地区也不代表一定安全——机房 IP、频繁切换节点、支付信息与出口对不上，同样会被风控盯上。本页给出的是风险提示，不是对账号命运的判决。
为什么 ChatGPT 和 Claude 显示的出口 IP 不一样？
因为代理软件按规则分流：不同域名命中不同的规则，就会从不同的节点出去。每一行的出口都是那家服务自己的 Cloudflare 边缘在 /cdn-cgi/trace 里报告的，是它真正看到的地址。不同服务之间出口不同问题不大；同一家的几个入口（比如 chatgpt.com 与 api.openai.com、claude.ai 与 api.anthropic.com）出口不一致才值得处理——同一个账号的请求一会儿从美国来、一会儿从日本来，是风控最常见的触发条件之一。
Gemini 那一行为什么看不到出口？
Google 的服务不经过 Cloudflare，也没有任何允许网页跨域读取、又会回显访客 IP 的公开地址，所以浏览器只能测出「连不连得上、多快」。本页不会拿别的服务的出口去冒充 Google 看到的出口。想确认 Google 走的是哪个出口，可以在代理软件的连接日志里找 generativelanguage.googleapis.com 与 gemini.google.com 命中的规则。
时区和出口不一致，会有什么影响？
网页和客户端都能直接读到系统时区，「IP 在美国、时区却是东八区」是识别代理最常用、成本最低的线索之一；据公开的逆向分析，Claude Code 还会专门读取系统时区。本页只在两者明显对不上时提醒（相差超过一小时、且出口国家在对照表里），邻近地区之间不报。完整的浏览器环境检查（时区、语言、字体、WebRTC 等十项）见本站的 Claude 检测。
本站会记录这次检测的结果吗？
不会。所有请求都由你的浏览器直接发给各家服务，不带 Cookie、不带来源页面，结果只显示在当前页面上，一个字节都不会发回本站，也没有历史记录。本站在页面上印出的「本站看到的地址」是打开本页时那次 HTTP 连接的来源地址，这一页因此不会被任何缓存保存。
